# Liholiswano Comprehensive Audit — 2026-10-04

## Scope
This audit covers the active `bnb-app-complete` branch, the customer dApp, owner/admin console, Solidity contracts, API/security boundary, CI, deployment configuration and current Render services. This is a cleanup audit, not a restart.

- Testnet only; no real-money operation.

## Critical code findings addressed
1. **Zero-bid rotation winner bug:** settlement now explicitly selects the first eligible member before applying the highest-bid comparison, so a previous winner cannot be selected again merely because all current eligible bids are zero.
2. **Customer collateral approval mismatch:** the customer dApp now separates collateral approval from contribution approval and automatically requests the correct approval when needed for Join/Contribute.
3. **Customer/owner UI separation:** the owner console no longer exposes customer join, contribution or bid controls. Privileged protocol controls are enabled only when the connected wallet matches the on-chain protocol owner.
4. **Stale deployment documentation:** BNB Testnet addresses were refreshed to match the current browser configuration.
5. **Testnet RPC consistency:** browser configuration now uses the documented BSC Testnet RPC endpoint with chain ID 97.

## Architecture
Customer:
`Customer → Liholiswano dApp → EVM wallet → BNB Smart Chain → Liholiswano contract → test token`

Operations:
`Render API → accounts/KYC/compliance/indexing/reconciliation/support`

Financial authority:
`Liholiswano smart contract`

The API must not custody customer funds or become an alternate financial ledger.
