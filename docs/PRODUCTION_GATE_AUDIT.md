# Liholiswano Production Gate Audit\n\n## Financial authority\n\nThe Solidity Liholiswano contract is the authoritative financial controller.\n\nThe API, web application, WhatsApp channel, indexer, reconciliation workers and keeper services must never become alternative ledgers or custodians of customer funds.\n\nThe off-chain system may authenticate customers; enforce KYC/AML eligibility before preparing restricted operations; prepare transaction requests; relay status; index events; reconcile database projections against chain state; operate a permissionless keeper; and notify customers.\n\nThe off-chain system must not directly debit customer balances, invent a payout, override contract settlement, mark an on-chain transaction confirmed without receipt verification, or move group escrow independently of the contract.\n\n## Current Solidity controls\n\nThe contract contains per-group escrow accounting, approved-token allowlisting, exact ERC20 transfer checks, reentrancy protection, contribution and bid deadlines, bid limits, automatic group locking, permissionless settlement, default handling, winner rotation, protocol fee and treasury, two-step ownership transfer, financial events, and escrow/token conservation tests.\n\nThe source branch now also contains an owner-controlled emergency pause for financial entrypoints. This source improvement requires deployment of a new contract version before it exists on the currently deployed Testnet contract.\n\nAn emergency pause is deliberately not a withdrawal/rescue function: pausing must not give an operator a path to extract customer escrow.\n\n## Customer authorization\n\nCustomer -> WhatsApp/Web -> API -> verified wallet -> customer wallet signature -> Solidity contract.\n\nTransaction recording verifies request ownership, transaction hash, chain ID, sender, contract target, called Solidity function, on-chain group ID, and successful receipt.\n\n## WhatsApp security\n\nWhatsApp account linking uses a one-time six-digit code, hashed code storage, ten-minute expiry, single-use token, normalized unique phone ownership, verified-phone requirement before account actions, provider webhook signature validation, provider verification-token validation, and duplicate-message protection.\n\nA WhatsApp message never receives custody of funds.\n\n## Reconciliation\n\nThe system maintains independent event-indexing and reconciliation state.\n\nReconciliation compares on-chain groups, members, escrow, contract token balances, transaction receipts, ERC20 transfers, customer wallet mappings, and financial ledger projections. Open discrepancies require an explicit operator resolution note.\n\n## RPC gate\n\nBSC public RPC endpoints are not treated as production indexing infrastructure. A dedicated BSC_RPC_URL is supported and REQUIRE_DEDICATED_RPC=true can force production indexing/reconciliation to fail closed when a dedicated provider is absent.\n\n## Remaining external activation gates\n\nThese cannot be honestly completed by code alone without provider credentials/configuration: dedicated BSC RPC provider; WhatsApp Business credentials; transactional email credentials; biometric KYC provider credentials; AML/PEP/sanctions provider credentials; production custody/keeper signing architecture; production USDT or USDC selection and contract address; independent smart-contract audit; Botswana/Eswatini legal and regulatory approval.\n\nThese are activation gates, not reasons to redesign the blockchain architecture.\n\n## Dependency gate\n\nCI now requires a package lockfile, uses npm ci, runs contract/API/web checks and performs a production dependency audit. If the repository initially lacks package-lock.json, CI bootstraps it once and then enforces locked installation.\n\nNo npm audit fix --force is used.\n\n## Mainnet rule\n\nThe current BSC Testnet deployment remains a test environment.\n\nMainnet deployment must use chain ID 56, a production contract deployment, production stablecoin configuration, dedicated RPC, production custody/keeper controls, audited Solidity bytecode, rehearsed database/reconciliation/indexing, verified KYC/AML/WhatsApp/email integrations, and completed legal/compliance gates.\n\nNo testnet contract address or MockUSDT address may be promoted to Mainnet.
